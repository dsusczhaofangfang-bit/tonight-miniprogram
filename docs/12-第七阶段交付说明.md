## 1. 本阶段做了什么

1. **独立角色与会话**：`services/auth.js` 开放 `bartender`；调酒师会话单独存 `lm_bartender_session`，与老板 `lm_admin_session` 互不覆盖，同一台设备可同时保持两种身份。口令 `1234` 只写在 `config/index.js`，页面不硬编码。
2. **独立入口**：「我的」页新增「调酒师工作台」（未登录显示「需口令」），与「老板管理后台」并列；进入需口令，登录后显示「调酒师 · 已登录」并可单独退出。
3. **工作台**（`pages/bartender-board`）：
   - 三个筛选：待接单 / 制作中 / 已完成（带计数），不含「已取消」与「全部」；
   - 桌号/编号搜索、按下单时间排序（先到先做 / 最新在前）；
   - 卡片突出桌号、商品与数量、备注、异常、状态，操作按钮 76rpx 高；
   - 新单静态高亮 + 「新」角标 + 顶部「新订单 N 单」提示条；
   - 提示音开关（本地 wav，偏好持久化）；
   - 在线/离线、最后更新时间；**常驻「模拟实时 · N 秒轮询」标注**。
4. **订单详情**（`pages/bartender-order`）：编号、桌号、下单时间、商品名称与数量、整单备注（作为制作要求）、异常说明、状态记录；操作只有「确认接单」「制作完成」和「提交异常说明」。
5. **状态机**：仍为 4 态 `待接单 → 制作中 → 已完成`（+ 已取消）。**按你确认，不加「待取餐」**；「制作完成」即进入已完成/历史记录。
6. **权限边界**：调酒师不能取消订单、不能处理异常、不能改商品/价格、看不到营业额与订单金额；老板页面被角色守卫拦下。服务层同样拒绝越权（4018 / 4020 / 4021）。
7. **异常协作**：调酒师提交原因（缺货/无法制作/酒具不足/其他 + 补充说明）→ 订单状态不变、老板端出现「异常待处理」→ 老板处理后写回时间线。
8. **实时抽象层**：`services/order-feed.js` 统一 `createOrderFeed({ intervalMs, onPoll, onError })`；Mock 用 `setInterval`，M4 只需替换为 CloudBase `watch`，页面不动。轮询只在页面可见时运行，页面隐藏/退出即停止。
9. **冲突处理**：状态更新带期望状态（乐观锁），别端已改单时返回 4017，页面提示「订单状态已变化」并自动刷新，避免覆盖顾客取消或老板操作。

## 3. 与原始需求的差异（已确认）

| 需求原文 | 实际实现 | 原因 |
| --- | --- | --- |
| 待接单 → 制作中 → **待取餐** → 已完成 | 待接单 → 制作中 → 已完成 | 你明确「仍然去掉待取餐」；`verify_stage7` 断言状态枚举仍为 4 个 |
| 商品备注和特殊制作要求 | 整单备注作为制作要求展示 | 现有订单模型只有整单备注；单品级备注需动购物车/确认页/快照，未在本期做 |
| 新订单视觉提醒 | 静态高亮 + 「新」角标 + 顶部提示条 | 遵守「全站仅欢迎页有动效」约束，未加脉动/闪烁 |
| 声音提醒（可开关） | 本地 wav + 开关持久化，离线/静音静默降级 | 演示环境无推送通道，提示音只在本页可见时播放 |

## 4. 测试步骤

> 前置：编译后进入「我的」→「调酒师工作台」，输入 `1234`。

1. **登录与隔离**：错误口令提示「口令错误」；`8888` 不能进调酒师端；`1234` 不能进老板后台。登录后返回「我的」，老板入口仍显示「需口令」（两份会话独立）。
2. **首屏**：默认「待接单」，三个筛选带计数，无「全部」与「已取消」；顶部显示「在线」「模拟实时 · 5 秒轮询」「更新 HH:mm:ss」。
3. **新单提醒**：用顾客端下单（酒单加购 → 结算 → 提交），5 秒内工作台出现「新订单 N 单」提示条，卡片带「新」角标，并播放提示音。
4. **提示音开关**：关闭开关后新单仍提醒但不出声；杀掉小程序重进，开关状态保留。
5. **快捷操作**：卡片点「接单」→ 状态变「制作中」，顾客端「我的订单 → 制作中」同步；点「制作完成」→ 变「已完成」，进入已完成筛选。
6. **搜索与排序**：输入桌号 `A1` 只剩该桌；输入不存在的桌号显示空态；切换「先到先做 / 最新在前」顺序变化。
7. **详情**：点卡片查看编号、桌号、时间、商品与数量、备注、状态记录；底部只有「确认接单 / 制作完成」，没有取消、没有金额与营业额。
8. **异常**：详情 →「提交异常说明」→ 选「缺货」并补充 → 提示已通知老板；工作台卡片与老板端出现「异常待处理」；老板处理后调酒师端显示「老板已处理」。
9. **越权**：调酒师直接打开 `pages/admin-overview/admin-overview` 被重定向到老板登录页；调酒师登录后打开老板页同样被拦。
10. **离线**：断网后顶部变「离线」并暂停轮询；恢复网络自动补拉并继续。
11. **冲突**：顾客提交订单后老板先接单，调酒师再点「接单」→ 提示「订单状态已变化，请刷新后重试」，列表自动刷新为制作中。
12. **重启**：关闭小程序重开，订单、状态、调酒师登录态（本地会话）仍在；「我的 → 开发自检 → 重置演示数据」可恢复演示订单。
13. **命令行**：`node scripts/verify_stage7.js` 应 56 项全过；回归 `verify_stage3/5/6.js` 分别 41 / 53 / 46 全过。

## 5. 已知限制 / 未完成

1. **不是真实时**：Mock 阶段为 5 秒本地轮询，页面已常驻「模拟实时」标注；M4 换 `order-feed` 为云端订阅后，才可写「实时推送」。
2. **单品备注**未做：特殊要求目前只能写整单备注。
3. **员工权限管理**未做：口令与角色都是本地 Mock，正式版权限必须由云函数校验。
4. 提示音是程序生成的短提示音，不是品牌音效；正式版可替换 `assets/sounds/order-alert.wav`。
5. 工作台不处理「已取消」订单（避免调酒师误操作），取消与异常处理归老板。
6. 文档同步：`docs/01` 的页面清单未新增调酒师页；如需并入需求文档，可下一轮补。
