## 1. 本阶段做了什么

1. **酒单页重做**：左侧竖排分类栏（全部 + 四个分类）、常驻搜索、右侧编辑式商品列表；每条含酒标式占位块（有图则显示真实图片）、名称、英文名、两行简介、价格、详情入口、加入购物车入口；加载骨架与空态。

## 3. 商品数据结构

```js
// 分类：id 即商品的 category 取值
{ id: 'traditional', name: '传统饮品', nameEn: 'Classics', sort: 10, enabled: true }

// 商品（24 款示例，每类 6 款）
{
  id: 'p_traditional_01',      // 唯一标识
  name: '示例·传统饮品 01',
  nameEn: 'Demo Classics 01',  // 英文名，展示用
  category: 'traditional',     // traditional | signature | non_alcoholic | snacks
  price: 5800,                 // 单位：分
  description: '示例数据：风味、配方与口感待替换为真实酒单内容。',
  image: '',                   // 空 → 酒标占位块；填本地/云存储路径 → 显示真实图片
  isAvailable: true,           // false → 酒单不展示、不可加购、购物车自动剔除
  tags: ['示例'],
  abv: null,
  sort: 10
}
```

- 分类与搜索统一走 `services/products.listProducts({ category, keyword })`；M4 换云函数只改这一层。
- `image` 支持本地路径（如 `/assets/images/products/x.jpg`）与云存储 `cloud://` 地址；加载失败会自动退回占位块。

## 4. 测试步骤（对应本次八条验收）

前置：微信开发者工具导入 `D:\小程序` → 编译。改过 `utils/mock-data/` 后 `seedVersion` 已递增，无需手动清缓存；若仍看到旧数据，进「我的 → 开发自检 → 重置演示数据」。

1. **四个分类切换**：底部「酒单」→ 左侧依次点「全部 / 传统饮品 / 特调饮品 / 无酒精饮品 / 小吃」。预期：右侧列表与「共 N 款」同步变化（全部 24、每类 6）；激活项左侧出现 4rpx 玫瑰红竖条；切换时先出现静态骨架再出列表。
2. **首页带入分类**：首页点「特调饮品」→ 自动跳到酒单且已选中「特调饮品」，列表只剩 6 款；再回首页点「小吃」同样正确。
3. **搜索**：酒单搜索框输入「特调」→ 6 款；输入「demo classics」（不分大小写）→ 6 款；输入「zzz」→ 空态「没有找到相关酒品」；点「清除」恢复当前分类全部；搜索时切换分类，关键词保留、结果按新分类重新过滤。
4. **进入详情**：点条目任意位置或「详情」→ 进入对应商品详情，标题为商品名；不存在的 id（如 `pages/product/product?id=x`）显示「商品不存在」。
5. **数量选择**：详情页「−」在 1 时不可再减；「＋」到 99 后不可再加；数量只影响本次加购。
6. **加入购物车**：详情页选 3 件 → 「加入购物车」→ 提示「已加入 3 件」，购物车 Tab 角标 +3；酒单条目「加入」→ 每次 +1，同款合并；打开购物车核对单价、数量、小计、合计（分为单位、展示两位小数）；首页、酒单、详情、购物车四处角标一致；关掉小程序重进仍保留。
7. **图片两种情况**：
   - 空：默认全部商品 `image: ''`，酒单与详情都显示酒标式占位块（分类名 + 示例图标注）。
   - 有图：临时给 `utils/mock-data/products.js` 的任一款填 `image: '/assets/icons/tab-menu.png'`，递增 `config/index.js` 的 `seedVersion`，重编译 → 酒单该条目与详情顶部显示真实图片（`aspectFill` 裁切）；再把 `image` 改成不存在的路径 → 自动退回占位块，不留白。验证后改回空字符串。
8. **无报错**：开发者工具 Console 无红色报错；WXML 面板无「未找到组件 / 属性类型错误」；切页、搜索、加购、下拉刷新均无异常。

- **返回保留**：从详情返回酒单，当前分类与关键词保持；下拉刷新酒单可重新拉取。
- **断网**：全部本地 Mock，断网重编译仍可用。

## 5. 设计取舍与偏离

1. **没有做双列「卡片」**：用户要求「商品卡片」，而 `docs/04` §3 明确不做双列卡片货架、`docs/05` §3.3 已定编辑式列表。本阶段按已确认的视觉准则做成单列编辑式条目——仍有图片/占位块、名称、价格、简介、详情与加购入口，信息一项不少。若确实想要双列图片卡，需要先确认推翻视觉准则。
2. **搜索限定在当前分类内**：默认「全部」时即为全局搜索；选中某分类后只在该分类内过滤。理由：分类栏常驻、24 款量级下可预期。要改成跨分类全局搜索，只需调整 menu 传参，不需要动页面结构。
3. **酒单「加入」固定 1 件，详情按所选数量**：与购物车合并逻辑一致，避免列表页出现数量选择器造成误触。
4. **无新增动效**：骨架为静态占位，分类激活条只用 180ms 的 `transform / opacity` 反馈，符合「全站仅欢迎页有动效」。
5. **`product-card` 组件未删除**：改为新字段并支持真实图片，但酒单已不引用，按 `docs/05` §6 保留。
