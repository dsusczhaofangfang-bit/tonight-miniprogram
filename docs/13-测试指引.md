## 0. 前置与准备

1. 开发者工具「编译模式」预置了两个扫码入口：`pages/welcome/welcome?table=t_a1`（桌号 A1）与 `?table=t_b2`（桌号 B2）。
2. 没有真实二维码时，用「我的 → 开发自检 → 当前桌号（调试）→ 选择桌号」，等价于扫码（仅开发版显示）。
3. 演示口令：老板 `8888`，调酒师 `1234`。
4. 需要恢复演示数据时：「我的 → 开发自检 → 重置演示数据」。

## 1. 冒烟测试（M0）

1. 编译后进入欢迎页，等待 0.6s 后点「跳过」或 1.15s 后点「进入酒馆」→ 首页。
2. 切换底部「酒单」：四个分类可切换，商品列表随分类变化。
3. 点商品条目进入详情；「加入」或详情页「加入购物车」会真实写入购物车（Mock）。
4. 「我的 → 开发自检」：8 项检查应全部为绿色（店铺、分类、商品、桌号、订单、今日数据、管理员会话、Mock 开关）。
5. 点「重置演示数据」→ 确认 → 重新检测仍全部正常。
6. 完全关闭小程序再打开，订单等本地数据仍然存在（storage 持久化）。

## 2. 欢迎页（纯文字排版）

> 玫瑰与花瓣效果已放弃。字体细节见 [08-欢迎页字体核实](08-欢迎页字体核实.md)。

1. **动画时序**：0.10s 品牌名、0.24s 英文名、0.56s 主欢迎语、0.72s 补充语、0.86s 英文副标题、0.60s「跳过」可点、1.15s「进入酒馆」可点（品牌名与下方文字之间停顿最长）。
2. **字体**：品牌名 **Tonight** 用 Georgia 衬线；其余中文与英文副标题为八公明朝子集，整体仍是衬线体系。
3. **已知混排**：过、样、欢、进、馆 5 个字来自思源宋体 SC，已按八公明朝字宽（650/1000）压缩并补到相同笔画粗细，正常应看不出明显差别。
4. 文字全程不抖动、不重排；安全区在刘海屏上不被遮挡。
5. 断网后重新编译仍正常（字体以 base64 内嵌，不走网络）。
6. 字体加载失败时整页退为系统衬线，不应出现豆腐块（方框）。

## 3. 首页（第二阶段）

1. 欢迎页「进入酒馆」→ 首页：品牌名、英文、介绍、四个分类、3 款今晚推荐、3 条当季推荐全部显示。
2. 点「特调饮品」→ 跳到酒单且已选中该分类，列表只剩 6 款；「小吃」同样自动筛选。
3. 点任一推荐商品 → 进商品详情；点「加入购物车」，购物车 Tab 角标同步。
4. 购物车：改数量、移除、清空，合计金额与「单价 × 数量」一致（分为单位，展示两位小数）。
5. 角标数量在首页、酒单、详情、购物车四处保持一致；关掉再进仍保留（storage）。
6. 首页右上角「我的」→ 我的页；「我的订单」入口与底部 Tab 进入同一页面。
7. 编译模式加路径 `pages/home/home?table=t_a1` → 首页显示「当前桌号 A1」；无参数则不显示。
8. 下拉刷新首页可重新拉取数据；断网重编译仍正常（全部本地 Mock）。

## 4. 酒单与商品详情（第三阶段）

> 完整验收步骤见 [09-第三阶段交付说明](09-第三阶段交付说明.md) 第 4 节。

1. 底部「酒单」：左侧「全部 / 传统饮品 / 特调饮品 / 无酒精饮品 / 小吃」切换，右侧列表与「共 N 款」同步（全部 24、每类 6），激活项有 4rpx 玫瑰红竖条。
2. 首页点「特调饮品」→ 酒单已选中该分类，列表 6 款。
3. 搜索框输入「特调」→ 6 款；输入 `demo classics`（不分大小写）→ 6 款；输入 `zzz` → 空态；点「清除」恢复。
4. 点条目或「详情」→ 详情页标题为商品名；「加入」/「加入购物车」→ 角标同步、购物车可核对数量与合计。
5. 详情页数量：1 时「−」不可点，99 时「＋」不可点；选 3 件加购，购物车应为 3 件。
6. 无图时酒单与详情显示酒标占位块（分类名 + 示例图）；临时给某款填 `image` 并递增 `seedVersion` 后显示真实图片，改成无效路径应自动退回占位块。
7. 把某款 `isAvailable` 改为 `false` 并递增 `seedVersion`：酒单少一款，其详情显示「已下架」且不可加购。
8. 从详情返回酒单，分类与关键词保持；下拉刷新可重新拉取。

## 5. 订单流程（第五阶段）

> 完整验收步骤见 [10-第五阶段交付说明](10-第五阶段交付说明.md) 第 4 节。前置：桌号只能由扫码参数带入（不做手动选桌）。

1. 设置桌号：编译模式选「扫码进入 · 桌号 A1」，首页应显示「当前桌号 A1」；桌号存入本地，之后启动一直保留。
2. 酒单加购 2 款 → 购物车：可单独勾选、全选；底部「已选 N 件 / 合计」只算勾选商品；一件未选点「去结算」会提示先勾选。
3. 点「去结算」→ 订单确认页：桌号 A1、商品图或占位块、单价、数量、小计、备注、订单总额。
4. 改数量 → 金额即时更新；返回购物车数量一致。
5. 填备注（≤100 字）→「提交订单」→ 提示「下单成功」并跳订单详情；订单编号形如 `20261102-0001`。
6. 回购物车：只清掉已提交的商品，未勾选的还在；角标同步。
7. 「我的订单」Tab：打开默认「待接单」；切「制作中 / 已完成 / 已取消」列表与空态同步；点卡片进详情。
8. 详情页「取消订单」（仅待接单可点）→ 状态变「已取消」；新下一单用底部「模拟推进」：待接单 → 制作中 → 已完成。
9. 杀掉小程序重进 → 订单与状态仍在；「重置演示数据」可恢复 4 条覆盖各状态的演示订单。
10. 命令行：`node scripts/verify_stage5.js`，应 53 项全部通过。

## 6. 老板管理端（第六阶段）

> 完整验收步骤与结果见 [11-第六阶段交付说明](11-第六阶段交付说明.md) 第 8 节。演示口令 `8888`。

1. 我的 →「老板管理后台」→ 输入 `8888` → 进入「经营概览」；顶条显示「老板管理 · 演示数据」。
2. 未登录时点入口只到口令页；输错口令提示「口令错误」；在「编译模式」直接打开 `pages/admin-overview/admin-overview` 会被重定向回登录页。
3. 订单管理：默认「全部」，切换四个状态筛选，计数与列表一致；点卡片看详情（编号 / 桌号 / 时间 / 单价·数量·小计 / 备注 / 总额 / 时间线）。
4. 详情点「确认接单」→ 顾客端「我的订单 → 制作中」同步；再点「完成制作」→ 顾客端变「已完成」。
5. 详情可「取消订单」（必须填原因）与「标记异常 / 处理异常」，操作写入状态记录。
6. 商品管理：新增商品（价格按元填，如 `58.5`）→ 酒单出现；编辑名称/价格/分类/介绍 → 酒单同步；行尾开关上下架。
7. 下架商品：酒单不显示、详情不可加购、购物车里自动剔除、下单被拒。
8. 改价后打开改价前的订单：单价与总额仍是旧价（快照）。
9. 概览四项数字随下单 / 取消 / 上下架变化；「已取消不计入」。
10. 关闭小程序重开：登录态、商品改动、订单状态都还在。
11. 命令行：`node scripts/verify_stage6.js`，应 46 项全部通过。

## 7. 调酒师工作台（第七阶段）

> 完整步骤与文件清单见 [12-第七阶段交付说明](12-第七阶段交付说明.md) 第 4 节。演示口令 `1234`；状态仍为 4 态，**没有「待取餐」**。

1. 我的 →「调酒师工作台」→ 输入 `1234` → 进入工作台；顶部显示「在线」「模拟实时 · 5 秒轮询」「更新 HH:mm:ss」。
2. 默认「待接单」，三个筛选带计数（无「全部」、无「已取消」）；用顾客端下单，5 秒内出现「新订单 N 单」提示条与「新」角标，并播放提示音。
3. 关闭「提示音」后新单仍提醒但不出声；重开小程序开关保留。
4. 卡片「接单」→ 顾客端「我的订单 → 制作中」同步；「制作完成」→ 两端都变「已完成」。
5. 桌号搜索 `A1`、切换「先到先做 / 最新在前」；点卡片看详情（编号 / 桌号 / 时间 / 商品与数量 / 备注 / 状态记录）。
6. 详情「提交异常说明」→ 选缺货并补充 → 老板端出现异常；老板处理后调酒师端显示已处理。调酒师不能取消订单。
7. 调酒师直接打开老板页会被拦回老板登录页；`8888` 进不了调酒师端。
8. 断网显示「离线」并暂停轮询，恢复后自动继续；命令行 `node scripts/verify_stage7.js` 应 56 项全过。

## 8. 命令行自检

四个脚本只用 Node 内置模块，不需要 `npm install`：

```bash
node scripts/verify_stage3.js   # 41 项：酒单 / 搜索 / 详情 / 加购 / 下架
node scripts/verify_stage5.js   # 53 项：购物车 / 下单 / 金额快照 / 状态机
node scripts/verify_stage6.js   # 46 项：老板端权限 / 商品增改 / 统计口径
node scripts/verify_stage7.js   # 56 项：调酒师端权限 / 轮询提醒 / 异常流转
```

一次跑完（任一失败即中断）：

```bash
node scripts/verify_stage3.js && node scripts/verify_stage5.js \
  && node scripts/verify_stage6.js && node scripts/verify_stage7.js
```

四个脚本末尾都会打印「通过 N 项，失败 0 项」，退出码 0 才算通过。CI 也跑同一组命令，见 [`.github/workflows/verify.yml`](../.github/workflows/verify.yml)。
