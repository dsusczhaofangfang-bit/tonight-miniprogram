## 1. 本阶段做了什么

1. **购物车支持勾选结算**：每条可单独勾选/取消、「全选」一键切换；底部「已选 N 件 / 合计」只算勾选商品；未勾选时「去结算」禁用并提示。
2. **订单确认页**（新增）：当前桌号、已勾选商品（图片或酒标占位块、单价、数量、小计）、订单总额、备注（≤100 字）、提交按钮；数量可改并同步回购物车。
3. **下单**：提交前由服务层按商品表重新核价（页面金额不采信）；生成唯一订单编号；商品名称/单价/数量/分类写入**历史快照**；成功后只清除本次提交的购物车商品。
4. **我的订单**（重做）：状态筛选（待接单 / 制作中 / 已完成 / 已取消，默认「待接单」，**不设「全部」**）、订单卡（编号、状态、桌号、时间、商品摘要、件数、金额）、按筛选的空态、下拉刷新。
5. **订单详情**（新增）：编号、下单时间、桌号、商品清单、金额、备注、当前状态、状态时间线（含操作人）；待接单可取消；演示用「模拟推进」。
6. **状态机与迁移**：`待接单 → 制作中 → 已完成`，`待接单 → 已取消`；旧本地订单的 `accepted/ready` 自动迁移并补齐快照字段，不丢历史数据。
7. **桌号安全**：只从扫码参数 / 本地存储读取；缺失时确认页显示警示并拦截提交，**不生成、不猜测、不默认桌号**。

## 3. 订单数据结构与状态机

```js
// 订单（下单时写快照）
{
  id: 'o_1762...',                 // 内部 id
  orderNo: '20261102-0001',        // 日期 + 当天序号，唯一
  tableId: 't_a1', tableName: 'A1', tableArea: '吧台区',
  items: [{
    productId, name, nameEn,
    category, categoryName, image,
    price,        // 下单时单价（分）
    qty, subtotal // 小计（分）
  }],
  totalQty, totalAmount,           // 件数 / 总额（分）
  status: 'pending',               // pending | making | completed | cancelled
  payStatus: 'unpaid',             // 本阶段不涉及支付
  payMode: 'mock',
  remark: '',                      // ≤100 字
  cancelReason: '',                // 取消时写入
  createdAt, updatedAt,
  statusLogs: [{ status, at, by, note }] // by: customer | admin | demo | system
}
```

状态机（`utils/constants.js` 的 `ORDER_TRANSITIONS`）：

```text
pending(待接单) ──► making(制作中) ──► completed(已完成)
      │
      └──► cancelled(已取消)

规则：只能前进；顾客仅 pending 可取消；admin（M3）可在 pending/making 取消；
      completed / cancelled 为终态；每次变更写 statusLogs。
```

- 订单编号：`YYYYMMDD-0001`，序号存在 `lm_order_seq` 里按天自增，并与已有订单查重，删除订单也不会重号。
- 快照：改商品价格、名称、分类都不影响历史订单（脚本已覆盖该用例）。
- 演示订单：首次运行或「重置演示数据」后生成 4 条，分别覆盖 待接单 / 制作中 / 已完成 / 已取消，便于验收筛选。

## 4. 测试步骤（对应本次 9 条验收）

前置：微信开发者工具导入 `D:\小程序` → 编译。**桌号只能由扫码参数带入**，任选一种方式设置：

- 编译模式选「扫码进入 · 桌号 A1 / B2」（已预置 `pages/welcome/welcome?table=t_a1`）；
- **没有真实二维码时**：进「我的 → 开发自检 → 当前桌号（调试）→ 选择桌号」，效果与扫码带入一致（只接受配置里启用中的桌号，仅开发版入口）；
- 订单确认页在未识别桌号时也会显示「调试：去『开发自检』选择桌号」。

桌号会写入本地，后续启动保留。

1. **购物车结算进入确认页**：加购 2 款 → 购物车勾选其中 1 款 → 底部合计只算勾选；点「去结算」→ 进入订单确认页。一件不勾选时按钮禁用并提示「请先勾选要结算的商品」。
2. **数量与金额**：确认页「＋/−」改数量 → 该行小计与订单总额即时变化；返回购物车数量一致。手动核对 `单价 × 数量` 与总额。
3. **备注**：输入备注（≤100 字，右下角有计数）；提交后详情页「顾客备注」显示一致。
4. **唯一订单编号**：提交后跳转订单详情，标题与信息卡显示 `YYYYMMDD-0001`；连续下两单编号递增不重复。
5. **购物车更新**：提交前留一件未勾选商品 → 下单后购物车只剩该件，角标同步；已提交商品被清除。
6. **列表与详情**：「我的订单」Tab 卡片含编号/状态/桌号/时间/摘要/件数/金额；点卡片进详情，编号、金额与列表一致。
7. **状态筛选**：打开默认「待接单」；依次切「制作中 / 已完成 / 已取消」，列表与空态同步（重置演示数据后 4 个状态各有 1 条）。筛选栏只有 4 项，没有「全部」。
8. **Mock 状态流转**：新下一单 → 详情页底部「模拟推进」→ 制作中 → 再点 → 已完成（每次都有确认弹窗，按钮带「演示」字样）；状态时间线同步新增记录。
9. **持久化**：完全关闭小程序再打开，「我的订单」数据与状态仍在；购物车勾选状态也在。

补充走查：

- **取消流程**：待接单订单点「取消订单」→ 二次确认 → 状态「已取消」，按钮消失；制作中/已完成没有取消按钮（制作中订单由演示种子提供）。
- **桌号缺失**：进「我的 → 开发自检 → 当前桌号（调试）→ 清除当前桌号」，再回购物车结算 → 确认页顶部红色「未识别到桌号」，提交按钮不可点，点提交提示重新扫码；不会生成任何桌号。
- **无商品**：购物车全不勾选时无法进入确认页；确认页若发现没有已勾选商品，显示空态与「返回购物车」。
- **异常路径**：商品在下单前被下架 → 提交返回「商品不可下单」；不存在的订单 id → 详情页显示空态。
- **旧数据**：升级前已有的 `已接单/待取餐` 本地订单会自动迁移为 `制作中/已完成`，「我的订单」不丢单。

## 5. 设计取舍与偏离

1. **状态机去掉「待取餐」**：按你的要求，最终为 `待接单 → 制作中 → 已完成`，取消为旁支；筛选也同步去掉「待取餐」。
2. **顾客取消只限「待接单」**：制作已开始后由店员介入更符合实际；服务层为 M3 预留了 `by: 'admin'`，可在待接单/制作中取消，但本阶段界面不暴露。
3. **「模拟推进」放在订单详情页底部**：没有后台时需要一个可演示状态流转的入口；按钮常驻「模拟」字样 + 二次确认弹窗，并写入操作人 `demo`，不会伪装成店员操作。M3 建后台后应替换。
4. **不做手动选桌**：需求原文有「结算页手动选择兜底」，但本次明确要求「桌号缺失时给出提示，不得随意生成」；顾客端只做扫码带入 + 缺失拦截，避免伪造桌号。
5. **开发版提供调试桌号入口**：调试阶段没有真实二维码，因此在「开发自检」页加了桌号选择（`picker`），只列配置里启用中的桌号、走 `app.setTable` 同一套校验；入口按 `envVersion` 判断，正式版不显示。桌号表也补了 `tableSeedVersion`，改 `utils/mock-data/tables.js` 后自动重建；启动时还会校验本地桌号是否仍存在/启用，失效则清空并回到「未识别桌号」。
6. **订单编号用日期 + 按天序号**：比纯时间戳更好口头核对；序号持久化并查重，删单不重号。
7. **兜底统计口径调整**：本阶段无支付，`stats` 由「已模拟支付」改为「未取消」，避免新订单不进营业数据；M5 接入支付后再按 `payStatus` 收口。
8. **无新增动效 / 阴影**：沿用现有规范；订单卡、筛选条、时间线均为静态样式，详情页没有底部面板阴影。
9. **筛选去掉「全部」（2026-11-02 补充）**：按你的要求，顾客端筛选只保留 待接单 / 制作中 / 已完成 / 已取消 四项，进页面默认「待接单」。`listOrders({})` 仍支持不带状态取全量，供后台与统计使用；页面对空状态参数直接忽略，不会退回不限状态的列表。
