## 1. 项目概述

### 1.1 定位

「柠舍唔同」是单体私人小酒馆。小程序服务两类用户：

- **到店顾客**：扫码进入 → 感受品牌 → 浏览酒单 → 确认桌号下单 → 到店取酒（本阶段无支付）。
- **老板（管理员）**：在小程序内置后台接单、更新订单状态、维护商品与分类、查看基础营业数据。

### 1.2 第一阶段目标

交付一个可在微信开发者工具与真机上完整运行、可向酒馆老板演示的 MVP。不接入真实支付与真实数据库；所有演示数据明确标注「示例」。

### 1.3 成功标准（演示脚本）

1. 打开小程序 → 纯文字欢迎页（文字依次淡入）→ 点击「进入酒馆」
2. 首页浏览品牌与分类入口
3. 酒单页切换四个分类、浏览商品
4. 打开商品详情 → 加入购物车
5. 购物车调整数量
6. 结算 → 确认桌号（由扫码带入，缺失即拦截）
7. 提交订单 → 订单进入「待接单」（本阶段无支付入口，M5 再接真实微信支付）
8. 进入「我的」→ 管理员入口 → 演示登录
9. 后台看到新订单 → 接单 → 制作中 → 完成
10. 后台查看历史订单与今日数据

全部 10 步无报错、无白屏，前后数据一致。

## 3. 总体设计

### 3.1 技术栈（固定）

- 微信原生小程序：JavaScript / WXML / WXSS
- CloudBase 云开发 + 云函数（第四阶段接入）
- Git 版本管理（先本地仓库）

不引入 Taro、uni-app 等跨端框架，不引入第三方 UI 组件库（降低维护成本；视觉全部自绘）。

### 3.2 分层架构

```text
页面 pages
   ↓ 只调用 services，不直接读写数据源
服务层 services（稳定 Promise 接口）
   ↓ 当前：Mock 实现；M4 后：云函数实现
数据源 mock-data / wx.storage  →  （M4 后）云数据库
```

关键约束：页面与 services 的接口在 Mock 与云端两个阶段保持一致，M4 只替换实现，不改页面。

### 3.4 Mock 策略

- 演示数据集中在 `utils/mock-data/`，全部带 `isDemo: true` 或文案前缀「示例」。
- 商品/分类的后台修改、订单数据通过 `wx.setStorageSync` 持久化；首次启动写入种子数据。
- services 统一返回 `Promise`，模拟 100–300ms 延迟，错误统一为 `{ code, message }`。
- `config/index.js` 的 `useMock` 控制数据源；M4 只替换 services 实现。
- 演示口令等开关集中在配置中，上线前整体移除。
- **示例数据规范**：商品名统一为「示例·」开头（如「示例·鸡尾酒 01」）；简介固定注明「示例数据，待替换为真实酒单」；价格使用常见区间但明确标注非真实价格；酒精度无真实数据时留空。

### 3.5 状态管理

- 购物车、当前桌号、管理员会话放进 `app.globalData`，并与 storage 双写。
- 页面 `onShow` 重新拉取关键数据，避免跨页不同步。
- 不引入 MobX / Redux 等第三方状态库。

### 3.6 视觉方向

复古爵士酒馆气质：墨黑与深胡桃木为底，深酒红与玫瑰红点缀，暖琥珀灯光，少量香槟金；衬线字体、留白、精致酒单排版。**禁止外卖平台式大红大黄、促销标签堆叠、密集卡片流。**

## 4. 功能需求

### 4.1 欢迎页

> **2026-11-02 二次变更：玫瑰与花瓣效果全部放弃，改为纯文字排版**（用户决定）。原玫瑰方案的技术文档保留在 `docs/07`，已废弃，仅作记录。

设计风格：**Typographic Luxury × Vintage Editorial**。纯文字，不出现图片、图标、装饰动画；不使用渐变、光晕、阴影、边框、分割线、玻璃拟态。层次只靠字号、字距、颜色与留白。

配色：

| 用途 | 色值 |
| --- | --- |
| 背景 | `#100D0E` |
| 主要文字（品牌名、主欢迎语、进入酒馆） | `#E8D9BE` |
| 英文与辅助文字（英文副标题、补充语、跳过） | `#B58A53` |

文案与层次（自上而下，视觉重心在品牌名）：

| 位置 | 文案 | 层级 |
| --- | --- | --- |
| 右上角 | 跳过 | 辅助，26rpx / 字距 5 |
| 品牌 | 柠舍唔同 | 主，120rpx / 字距 16 |
| 品牌下 | `COCKTAIL & WHISKEY BAR` | 辅，22rpx / 字距 9 |
| 欢迎语 | 今夜，来点不一样的。 | 次主，37rpx / 字距 6 |
| 补充语 | 欢迎来到柠舍唔同。 | 辅，28rpx / 字距 5 |
| 补充语下 | `A DIFFERENT KIND OF NIGHT.` | 辅，20rpx / 字距 7 |
| 底部安全区内 | 进入酒馆 | 主，32rpx / 字距 20，纯文字入口，无背景无描边 |

时序（纯淡入，总长 1.15s）：

| 时间 | 内容 |
| --- | --- |
| 0.10s | 「柠舍唔同」 |
| 0.24s | `COCKTAIL & WHISKEY BAR` |
| 0.56s | 主欢迎语 |
| 0.72s | 补充语 |
| 0.86s | `A DIFFERENT KIND OF NIGHT.` |
| 0.60s | 右上角「跳过」可点击 |
| 1.10s | 「进入酒馆」出现，1.15s 可点击 |

> 2026-11-02 微调：加长品牌名与下方欢迎语之间的停顿（0.24s → 0.56s），其余行间隔略微拉开；文案、字号、字距、配色与 520ms 淡入时长均未变。

字体：

- 全页统一八公明朝（`HakkouMincho`），子集内嵌，不引外部地址。
- 八公明朝缺 6 个简体字（过、柠、样、欢、进、馆），由思源宋体 SC 子集补齐，并压到八公明朝的字宽（650/1000 em）与笔画粗细，**属于已知混排**，详见 `docs/08`。
- 字体加载失败时整页回退到系统衬线（`Songti SC`/`STSong`），不出现豆腐块。

其它：

- 跳过与进入都进首页；`_leaving` 做重复点击去重。
- 适配不同屏幕与安全区（`env(safe-area-inset-*)`）。
- 不出现 HTML 实体乱码（`&` 写 `&amp;`）。

（是否记忆「已看过」并缩短动画，见待确认事项 P15。）

### 4.2 首页

> 2026-11-02 第二阶段：按用户要求重做首页，实现在此登记；版式细节见 `docs/05` 3.2。

- 顶部品牌区：中文名「柠舍唔同」、英文锁定组合、一句酒馆介绍（示例文案）；右上角「我的」入口。
- 扫码进入时显示当前桌号（`?table=t_a1` 或二维码 `scene`），桌号必须存在于配置且启用，非法参数忽略。
- 主入口：「开始点单」。
- 分类入口：传统饮品 / 特调饮品 / 无酒精饮品 / 小吃，四格同一套细线网格；点击进入酒单并自动筛选该分类。
- 推荐商品：3 款，含占位图块、名称、英文名、简介、价格、详情入口与加入购物车。
- 酒馆推荐：当季推荐 3 条，纯文字（酒名 + 一句话推荐语），点击进入详情。
- 底部导航：首页 / 酒单 / 购物车 / 我的订单。
- 商品暂无真实图片，用酒标式占位色块（深胡桃底 + 细金内框 + 分类名 + 「示例图」），**不伪造产品照片**；有真图后只填 `image` 字段即可替换。
- **首页不展示到店信息**（地址 / 营业 / 电话 / 地图导航）——2026-11-02 用户明确要求移除，原 M0 的门店信息卡不再出现在首页。

### 4.3 酒单

> 2026-11-02 第三阶段：酒单改版与商品详情完善，实现在此登记；版式见 `docs/05` 3.3。

- 分类：传统饮品 Classics / 特调饮品 Signature / 无酒精饮品 Non-alcoholic / 小吃 Snacks；分类 id 即 `traditional` / `signature` / `non_alcoholic` / `snacks`，来自分类配置，可增删与排序。首页分类入口与酒单共用同一份分类，不在页面里重复定义。
- 布局：左侧竖排分类栏（160rpx，「全部」+ 四个分类；激活项为 4rpx 玫瑰红竖条 + 米白文字）+ 右侧编辑式列表；不做双列卡片货架。
- 默认进入「全部」，展示全部在售商品；从首页分类入口进入时自动选中对应分类。
- 商品条目：酒标式占位块（有 `image` 时自动换成真实图片）、中文名、英文名、两行简介、价格、详情入口、加入购物车；条目之间只用细线分隔，不用圆角卡片与投影。
- 搜索：按酒名（中文名 / 英文名）关键词筛选，在当前分类内生效；无结果时给出可操作的提示。
- 状态：静态加载骨架、空分类提示；下架商品不展示。
- 商品详情：大图或占位块、分类、名称、简介、价格、数量步进器、加入购物车；下架商品显示「已下架」且不可加购。

### 4.4 购物车

- 列表：商品、单价、数量步进、小计、删除。
- 勾选：每条可单独勾选/取消，另有「全选」；底部合计只统计已勾选商品。
- 底部：已选件数与合计金额、清空、去结算。
- 去结算只带已勾选商品进入订单确认页；一件未选时按钮不可用。
- 空态引导去酒单。
- storage 持久化，跨启动保留（含勾选状态）；旧缓存没有勾选字段时默认全选。
- 金额一律以「分」计算，展示时转元。

### 4.5 桌号

- 桌号来自配置数组（id、名称、区域、排序、二维码参数、启用状态），不写死在页面。
- 进入方式：扫桌码（`pages/home/home?table=t_a1` 或二维码 `scene`）自动带入并存入本地；**不做结算页手动选桌**。
- 未识别到桌号时，订单确认页显示「未识别到桌号」并禁用提交，提示重新扫码；**不得自动生成、猜测或默认任何桌号**。
- 开发版可在「开发自检 → 当前桌号（调试）」里选择一个配置中的启用桌号，用于没有真实二维码时调试；该入口按 `envVersion` 判断，正式版不显示，且不改变「桌号来自二维码」的规则。
- 桌号表有独立 `tableSeedVersion`：修改 `utils/mock-data/tables.js` 后递增即可让本地缓存自动重建；启动时会校验本地桌号，失效则清空。
- 二维码：第一阶段后台可查看每桌二维码参数，不要求生成打印图。
- 默认示例：吧台区 A1–A4，散座区 B1–B4。

### 4.6 订单确认与订单管理（本阶段范围）

- 订单确认页（`pages/order-confirm/order-confirm`）：当前桌号、已勾选商品（名称 / 图片或酒标占位块 / 单价 / 数量）、商品小计、订单总额、备注（选填，最多 100 字）。
- 数量可修改，改动同步回购物车；金额按商品表实时重算。
- 提交前由服务层按当前商品表重新核价，页面传入的金额一律不采信；桌号必须存在且启用。
- 提交成功后生成唯一订单编号，只清除**本次已提交**的购物车商品，其余商品与勾选状态保留。
- 我的订单：按状态筛选（待接单 / 制作中 / 已完成 / 已取消，**默认「待接单」，不设「全部」**），卡片展示编号、桌号、时间、商品摘要、件数、金额；空态按筛选给出文案。
- 订单详情：订单编号、下单时间、桌号、商品清单（名称 / 单价 / 数量 / 小计）、订单总额、顾客备注、当前状态、状态时间线（含操作人）。
- 顾客取消：仅「待接单」可自助取消（二次确认并写入状态记录）；进入「制作中」后不可自助取消，提示联系店员；M3 后台可在待接单/制作中取消。
- 演示阶段在订单详情提供「模拟推进」按钮，仅用于演示状态流转，界面明确标注「演示」；M3 换成老板后台操作。
- **支付不在本阶段**：`payStatus` 保持 `unpaid`，不调用任何支付接口，界面不出现支付入口；M5 再接入。

### 4.7 管理后台（小程序内置）

入口与鉴权：

- 入口：「我的」页常驻「老板管理后台」；未登录点击先到管理口令页（演示口令 `8888`），已登录直接进概览，「我的」页同时出现「退出管理后台」。
- 原则：管理员身份必须服务端验证；正式版由云函数校验 openid 白名单 + 角色。前端入口可见与否、口令是否写在客户端，**都不构成安全边界**。
- 演示阶段：`authService` 本地模拟登录（`role: 'owner'`、`mock: true`），登录页与每个后台页面顶部常驻「演示鉴权 / 演示数据」标识；上线前替换逻辑并移除口令。
- 未登录访问后台页面 → 页面守卫（`utils/admin-guard`）重定向登录页，且不加载任何数据。

已实现（2026-11-02，第六阶段）：

1. **经营概览**：今日订单数、今日营业额、待处理订单（待接单 + 制作中）、在售商品数；已取消不计入订单数与营业额；待处理异常提示；最近 5 笔订单。
2. **商品管理**：列表（分类筛选、名称搜索、上下架状态与计数）、新增、编辑（名称/英文名/分类/价格/介绍/上下架）、上架/下架。**商品图片只读**：由系统维护者统一更新，管理端不提供上传。
3. **订单管理**：筛选（全部 / 待接单 / 制作中 / 已完成 / 已取消，带计数）、订单卡、详情（编号/桌号/下单时间/商品名称·单价·数量·小计/备注/总额/状态时间线）、状态推进、取消（必填原因）、异常标记与解除。

规划中（未实现）：

4. **分类管理**：新增、重命名、排序、启停；分类下存在商品时禁止删除。当前分类固定四个。
5. **历史订单**：按日期范围与状态筛选，分页加载。
6. **营业数据**：近 7 天订单数/营业额列表（不做复杂图表）。
7. 商品删除（当前只做上下架，避免误删影响历史订单）。

订单状态机：

```text
pending(待接单) → making(制作中) → completed(已完成)
pending → cancelled(已取消：顾客可在待接单取消；老板后台可在待接单/制作中取消，且必须填写原因)
```

- 状态只能前进，不可回退；每次变更写入 `statusLogs`（`by: customer | owner | demo | system`）。
- 操作按钮防重复点击；非法状态返回明确错误。
- 已取消 / 已完成的订单不可再变更。
- **不设「待取餐」状态**（2026-11-02 用户确认，顾客端与老板端一致）。
- 异常不新增状态：以订单上的 `exception` 旁挂字段记录原因与处理结果，便于后续调酒师端复用。

### 7.1 色板

| Token | 色值 | 用途 |
| --- | --- | --- |
| 墨黑 | `#0B0A09` | 页面底色（避免纯黑 `#000`） |
| 深胡桃木 | `#241610` | 卡片、区块底 |
| 深酒红 | `#5A1A24` | 强调区块、按钮底 |
| 玫瑰红 | `#A32B41` | 点缀、分类激活竖条、价格强调 |
| 暖琥珀 | `#D9A45B` | 暖光、按钮文字、高亮 |
| 香槟金 | `#C9A86E` | 细线、边框、次级文字 |
| 米白 | `#F4ECDF` | 主文字 |
| 灰褐 | `#A08F7E` | 次级文字 |

### 7.2 字体与字号

- 中文衬线优先：`"Songti SC", "Noto Serif SC", "STSong", serif`；英文：`Georgia, "Times New Roman", serif`。
- 若后续需要品牌字体，通过 `wx.loadFontFace` 加载（需授权与网络），当前使用系统字体。
- 字号：品牌标题 64rpx、页面标题 44rpx、区块标题 36rpx、正文 28rpx、辅助 24rpx。
- 字间距：标题 `letter-spacing: 4rpx`；英文全大写标题 `6rpx`。

### 7.3 布局与质感

- 间距基准 8rpx；页面左右留白 32rpx。
- 卡片圆角 16rpx；细金线分隔 `1rpx rgba(201,168,110,0.25)`。
- 图片统一叠暖色/暗角，保证同一视觉色调。
- 按钮：深酒红底 + 香槟金细边 + 米白字；主按钮高 88rpx。

### 7.4 动效原则

- 克制：仅欢迎页重动效；页面切换淡入；列表不做逐项动画。
- 所有动效时长 200–400ms（欢迎页除外），统一缓动 `ease-out`。

### 7.5 素材占位方案

| 素材 | 占位方案 | 后续替换 |
| --- | --- | --- |
| Logo | 文字标「柠舍唔同」+ 细金线框 | 替换 `assets/images/logo.*` |
| 门店照片 | 暖色渐变占位块 + 「示例图片」角标 | 替换 `assets/images/shop.*` |
| 商品图 | 纯色/渐变占位图 + 分类色 | 替换商品 `image` 字段 |
| 图标 | 内置 PNG 占位（线性风格） | 统一替换图标目录 |

> 欢迎页不使用任何素材（无图片、无花瓣、无边框），因此不再需要花瓣占位方案。

占位素材均在页面或文档标注「示例/占位」，替换时不改代码结构。
