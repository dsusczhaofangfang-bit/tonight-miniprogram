## 1. 项目概述

### 1.1 定位

「柠舍唔同」是单体私人小酒馆。小程序服务两类用户：

- **到店顾客**：扫码进入 → 感受品牌 → 浏览酒单 → 选桌下单 → 模拟支付。
- **老板（管理员）**：在小程序内置后台接单、更新订单状态、维护商品与分类、查看基础营业数据。

### 1.2 第一阶段目标

交付一个可在微信开发者工具与真机上完整运行、可向酒馆老板演示的 MVP。不接入真实支付与真实数据库；所有演示数据明确标注「示例」。

### 1.3 成功标准（演示脚本）

1. 打开小程序 → 玫瑰花瓣欢迎页 → 点击「进入酒馆」
2. 首页浏览品牌与店铺信息
3. 酒单页切换四个分类、浏览商品
4. 打开商品详情 → 加入购物车
5. 购物车调整数量
6. 结算 → 选择桌号
7. 提交订单 → 模拟支付（页面明确标注演示）
8. 进入「我的」→ 管理员入口 → 演示登录
9. 后台看到新订单 → 接单 → 制作中 → 完成
10. 后台查看历史订单与今日数据

全部 10 步无报错、无白屏，前后数据一致。

## 3. 总体设计

### 3.1 技术栈（固定）

- 微信原生小程序：JavaScript / WXML / WXSS
- CloudBase 云开发 + 云函数（第四阶段接入）
- Git 版本管理（先本地仓库）

不引入 Taro、uni-app 等跨端框架，不引入第三方 UI 组件库（降低维护成本；视觉全部自绘）。

### 3.2 分层架构

```text
页面 pages
   ↓ 只调用 services，不直接读写数据源
服务层 services（稳定 Promise 接口）
   ↓ 当前：Mock 实现；M4 后：云函数实现
数据源 mock-data / wx.storage  →  （M4 后）云数据库
```

关键约束：页面与 services 的接口在 Mock 与云端两个阶段保持一致，M4 只替换实现，不改页面。

### 3.4 Mock 策略

- 演示数据集中在 `utils/mock-data/`，全部带 `isDemo: true` 或文案前缀「示例」。
- 商品/分类的后台修改、订单数据通过 `wx.setStorageSync` 持久化；首次启动写入种子数据。
- services 统一返回 `Promise`，模拟 100–300ms 延迟，错误统一为 `{ code, message }`。
- `config/index.js` 的 `useMock` 控制数据源；M4 只替换 services 实现。
- 演示口令、模拟支付开关集中在配置中，上线前整体移除。
- **示例数据规范**：商品名统一为「示例·」开头（如「示例·鸡尾酒 01」）；简介固定注明「示例数据，待替换为真实酒单」；价格使用常见区间但明确标注非真实价格；酒精度无真实数据时留空。

### 3.5 状态管理

- 购物车、当前桌号、管理员会话放进 `app.globalData`，并与 storage 双写。
- 页面 `onShow` 重新拉取关键数据，避免跨页不同步。
- 不引入 MobX / Redux 等第三方状态库。

### 3.6 视觉方向

复古爵士酒馆气质：墨黑与深胡桃木为底，深酒红与玫瑰红点缀，暖琥珀灯光，少量香槟金；衬线字体、留白、精致酒单排版。**禁止外卖平台式大红大黄、促销标签堆叠、密集卡片流。**

## 4. 功能需求

### 4.1 欢迎页（核心视觉）

**硬性要求：玫瑰花瓣逐片掉落是整个欢迎页的绝对核心，不得用唱片、爵士乐器或普通酒吧背景替代玫瑰元素。**

流程与时序（建议值，可微调）：

| 时间 | 内容 |
| --- | --- |
| 0.0s | 墨黑背景渐入，花瓣开始逐片飘落 |
| 0.8s | 右上角出现「跳过」 |
| 1.0s | 「柠舍唔同」淡入并轻微上浮 |
| 1.6s | 「COCKTAIL & WHISKEY BAR」淡入 |
| 2.1s | 欢迎语「今夜，来点不一样的。欢迎来到柠舍唔同。」 |
| 2.6s | 「进入酒馆」按钮淡入，可点击 |
| 3.2s | 入场动画完成，花瓣持续循环飘落 |

花瓣要求：

- 数量 8 片，低端机降级为 4 片；3–4 种形态。
- 每片参数独立：大小 18–48rpx、下落时长 6–10s、起始延迟、旋转角度、透明度 0.5–0.95、横向漂移与运动轨迹。
- 前后景分层：2–3 片较大、透明度低、速度慢（背景层）；其余中速（前景层）；不得遮挡文字可读性。
- 循环飘落，非一次性动画。
- 实现方式：透明 PNG + WXSS 动画（绝对定位 + 预置 keyframes + 内联 duration/delay/opacity）；实测性能不足时才评估 Canvas。
- 占位素材：由脚本生成柔和边缘的玫瑰花瓣 PNG（3–4 种），明确标注为占位；不使用与门店无关的建筑、装饰生成图。
- 跳过：点击「跳过」直接进入首页；「进入酒馆」同样进入首页。
- 性能：动画期间不做高频 `setData`；离开页面即停止动画。
- 验收：首次进入时序完整；跳过可用；真机无明显卡顿；断网可播放（不依赖网络素材）。

（是否记忆「已看过」并缩短动画，见待确认事项 P15。）

### 4.2 首页

- 品牌区：中文名、英文名、slogan「今夜，来点不一样的。」
- 主入口：「开始点单」；次级入口：「查看酒单」。
- 店铺信息卡：地址、营业时间、电话（占位并标注示例）；地图/导航按钮预留，第一阶段点击提示「待完善」。
- 底部导航：首页 / 酒单 / 我的。

### 4.3 酒单

- 分类切换：鸡尾酒 Cocktail / 威士忌 Whiskey / 啤酒 Beer / 小食 Snacks；来自分类配置，可增删与排序。
- 商品卡：占位图、中文名、英文名、一句简介、价格。
- 商品详情：大图、名称、简介、价格、数量步进器、加入购物车。
- 状态：加载骨架、空分类提示；下架商品不展示。
- 第一阶段不做搜索。

### 4.4 购物车

- 列表：商品、单价、数量步进、小计、删除。
- 底部：合计金额、清空、去结算。
- 空态引导去酒单。
- storage 持久化，跨启动保留。
- 金额一律以「分」计算，展示时转元。

### 4.5 桌号

- 桌号来自配置数组（id、名称、区域、排序、二维码参数、启用状态），不写死在页面。
- 进入方式：① 扫桌码（`pages/home/home?table=t_a1`）自动带入；② 结算页手动选择兜底。
- 未选桌不可提交，提示「请选择桌号」。
- 二维码：第一阶段后台可查看每桌二维码参数，不要求生成打印图。
- 默认示例：吧台区 A1–A4，散座区 B1–B4。

### 4.6 提交订单与模拟支付

- 订单确认页：商品清单、数量、合计、桌号、备注（选填）。
- 提交 → 创建订单（`status=pending`，`payStatus=unpaid`，`payMode=mock`）。
- 模拟支付页：
  - 顶部醒目标识「演示模式」，正文「本页为模拟支付，不会产生真实扣款」。
  - 显示金额与订单号。
  - 「确认模拟支付」→ 成功后 `payStatus=mock_paid`，订单进入后台「待接单」。
  - 「暂不支付」返回，订单保留为未支付；未支付订单不计入后台营业数据。
- 订单详情：状态时间线（已提交 → 待接单 → 制作中 → 已完成）。
- **不得伪造真实支付结果**；后台订单明确展示「模拟支付」标识。

### 4.7 管理后台（小程序内置）

入口与鉴权：

- 入口：「我的」页长按底部版本号 2 秒 → 管理员登录页；隐藏入口不作为安全边界。
- 原则：管理员身份必须服务端验证；正式版由云函数校验 openid 白名单 + 角色。
- 演示阶段：`authService` 本地模拟登录（演示口令），所有后台页面顶部常驻「演示鉴权」标识；上线前替换逻辑并移除口令。
- 未登录访问后台页面 → 重定向登录页。

功能：

1. **工作台**：待接单数、制作中数、今日订单数、今日营业额（模拟支付口径）、快捷入口。
2. **商品管理**：列表（分类筛选、上下架状态）、新增、编辑（名称/英文名/分类/价格/简介/图片占位/排序）、上架/下架、删除（二次确认，建议优先下架）。
3. **分类管理**：新增、重命名、排序、启停；分类下存在商品时禁止删除。
4. **订单管理**：Tab（待接单/制作中/已完成/全部）；卡片（桌号、金额、时间、商品数）；详情（明细、备注、状态时间线）；操作按钮按状态机显示。
5. **历史订单**：按日期范围与状态筛选，分页加载。
6. **营业数据**：今日概览 + 近 7 天订单数/营业额列表（不做复杂图表）。

订单状态机：

```text
pending(待接单) → accepted(已接单) → making(制作中) → completed(已完成)
pending → cancelled(已取消，仅管理员可操作)
```

- 状态只能前进，不可回退；每次变更写入 `statusLogs`。
- 操作按钮防重复点击；非法状态返回明确错误。

### 4.8 店铺信息与全局配置

`shop` 配置集中管理：名称、英文名、slogan、地址、营业时间、电话、经纬度（预留）、公告。第一阶段全部占位并标注示例，不虚构真实信息。

### 7.2 字体与字号

- 中文衬线优先：`"Songti SC", "Noto Serif SC", "STSong", serif`；英文：`Georgia, "Times New Roman", serif`。
- 若后续需要品牌字体，通过 `wx.loadFontFace` 加载（需授权与网络），当前使用系统字体。
- 字号：品牌标题 64rpx、页面标题 44rpx、区块标题 36rpx、正文 28rpx、辅助 24rpx。
- 字间距：标题 `letter-spacing: 4rpx`；英文全大写标题 `6rpx`。

### 7.3 布局与质感

- 间距基准 8rpx；页面左右留白 32rpx。
- 卡片圆角 16rpx；细金线分隔 `1rpx rgba(201,168,110,0.25)`。
- 图片统一叠暖色/暗角，保证同一视觉色调。
- 按钮：深酒红底 + 香槟金细边 + 米白字；主按钮高 88rpx。

### 7.4 动效原则

- 克制：仅欢迎页重动效；页面切换淡入；列表不做逐项动画。
- 所有动效时长 200–400ms（欢迎页除外），统一缓动 `ease-out`。
