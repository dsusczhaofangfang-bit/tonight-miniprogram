## 4. 不可违反的约束

1. 不更换技术栈：微信原生 JavaScript / WXML / WXSS；不引入 Taro、uni-app、第三方 UI 库。
2. 不擅自重构或删除已完成模块；需要动 M0 页面时先说明原因与影响。
3. 每步先说明改哪些文件、为什么，得到用户批准再写代码；交付后先交用户验收，不自行判定通过。
4. 视觉遵循 `docs/04` 与 `docs/05`：
   - 不加任何 Logo、印章、水印；
   - 全站仅商品详情底部面板允许一层阴影；
   - 全站仅欢迎页有重动效；
   - 不做双列商品卡货架、不做眉标、不做全大写小标签（品牌英文锁定组合除外）。
5. 演示数据一律标注“示例”；商品名用“示例·”前缀；不虚构真实门店信息。
6. 金额统一以“分”存储与计算，展示时转元。
7. 正式版管理员鉴权、订单金额、订单状态必须服务端校验；演示阶段必须明确标注，不得伪装真实支付。
8. 欢迎页不记忆“已看过”（P15 默认），每次启动完整播放；“跳过”0.8s 后可用。
